# Simulation evaluation

Generated by `SimulationEvaluationTest` (`mvn test -Pevaluation` in `backend/`). Do not edit by hand.

## Method

30 simulated students (personas) each have a known true lean, from -1 to +1, on all 24 attributes. Each RIASEC letter is the strongest interest for 5 personas (+0.8), with a different second letter (+0.5); everything else is random from a fixed seed (20261118). A persona answers each question by picking the option whose evidence best agrees with its true leans (strength x direction x lean, added up). The personas go through the real assessment, recommendation and contest services with an in-memory database, so the questions asked, the stopping rule and the contest logic are exactly the app's. Per-persona results are in the CSV files next to this one.

## 1. Recovery: does the model end up believing what is true?

For each persona and attribute, the true lean (rescaled to 0..1) is compared with the model's final belief level after the normal assessment. 30 personas x 24 attributes = 720 pairs.

| Attributes | Pearson r | Mean abs. error | Got any evidence | Right direction |
|---|---|---|---|---|
| All | 0.68 | 0.16 | 86% (617/720) | 90% (351/391) |
| Interests | 0.75 | 0.15 | 79% (142/180) | 90% (82/91) |
| Work values | 0.57 | 0.17 | 84% (152/180) | 83% (77/93) |
| Work style | 0.69 | 0.15 | 94% (170/180) | 91% (100/110) |
| Abilities | 0.75 | 0.16 | 85% (153/180) | 95% (92/97) |

- **Pearson r**: how closely the model's levels rise and fall with the true levels (1 = perfectly in step, 0 = unrelated).
- **Mean abs. error**: the average gap between true level and belief level on the 0 to 1 scale. The model pulls uncertain beliefs toward 0.5 on purpose, so this is larger than the raw disagreement.
- **Got any evidence**: share of attributes that at least one asked question touched. Untouched ones stay at 0.5.
- **Right direction**: for clear true leans (at least 0.3 either way) that got evidence, how often the model leans the same way.
- **Flagged contradictory**: on average 1.8 of a persona's 24 attributes are flagged as contradictory (shown to the student as mixed evidence) after the assessment.

## 2. Top-3 accuracy: does a career from the right family make the top 3?

A persona's target family is every career whose O*NET interest code starts with the persona's strongest RIASEC letter. Five personas per letter.

| Family (first letter) | Careers in family | Top 3 has one | By chance |
|---|---|---|---|
| All | 25 | 87% (26/30) | 43% |
| Realistic | 4 | 60% (3/5) | 42% |
| Investigative | 6 | 100% (5/5) | 58% |
| Artistic | 2 | 100% (5/5) | 23% |
| Social | 5 | 100% (5/5) | 50% |
| Enterprising | 5 | 100% (5/5) | 50% |
| Conventional | 3 | 60% (3/5) | 33% |

- **Top 3 has one**: share of personas whose top 3 includes at least one career from their family.
- **By chance**: the same share if the top 3 were three careers picked at random from the 25.
- Lenient version (a top-3 career starts with either of the persona's two strongest letters): 100% (30/30).

## 3. Noise robustness: do a few careless answers change the result?

Each persona is run again with each answer independently replaced by a random option, with a 10% or 20% chance. Five runs per persona and noise level, each with its own fixed seed. Results are compared with the persona's clean run.

| Noise | Runs | Answers actually replaced | Same top match | Same top-3 set | Average overlap |
|---|---|---|---|---|---|
| 10% | 150 | 10% (299/3000) | 68% (102/150) | 42% (63/150) | 0.71 (2.14 of 3) |
| 20% | 150 | 21% (629/3000) | 54% (81/150) | 27% (40/150) | 0.61 (1.83 of 3) |

- **Same top match**: share of noisy runs whose first recommendation is the clean run's first.
- **Same top-3 set**: share of noisy runs whose three careers are the same as the clean run's (order ignored).
- **Average overlap**: careers shared with the clean top 3, as a fraction of 3.

## 4. Adaptivity: do different students get different questions?

Taken from the 30 clean runs. The first question is always the same, because nothing is known about the student yet; after that the next question depends on the answers so far.

| Measure | Value |
|---|---|
| Questions asked (mean) | 20.0 |
| Questions asked (min to max) | 20 to 20 |
| Distinct question sequences | 30 of 30 |
| Questions in the bank used by anyone | 36 of 37 |
| Average question-set overlap between two personas (Jaccard) | 0.56 |
| Average position where two sequences first differ | 4.7 |

- **Questions asked**: the assessment asks 12 to 20 questions; after 12 it stops early once nothing left is worth asking or the profile is clear enough. Every persona reached the 20-question cap, so the early stop never triggered for these personas.
- **Jaccard overlap**: questions both personas saw, divided by questions either saw (1 = same set, 0 = nothing shared).
- **First difference**: the question number at which two personas' sequences stop being identical.

## 6. Question curve: how much do more questions help?

One run per persona, answering honestly, with the beliefs and top 3 recorded after 8, 12, 16 and 20 questions. It uses the app's own question choice but never stops early, so every persona reaches every checkpoint. (The app itself asks at least 12 and at most 20.) Per-persona values are in question-curve.csv.

| Questions answered | Pearson r | Mean abs. error | Top 3 has a career from the family |
|---|---|---|---|
| 8 | 0.45 | 0.18 | 80% (24/30) |
| 12 | 0.55 | 0.18 | 77% (23/30) |
| 16 | 0.64 | 0.17 | 83% (25/30) |
| 20 | 0.68 | 0.16 | 87% (26/30) |

- Same measures as sections 1 and 2, pooled over all 30 personas at each point.
- Where a persona's normal run stopped, the curve run is checked to have asked the same questions and given the same top 3, so it follows the app exactly.

## 5. Contest behaviour: does pushing back work, and can honest answers undo a mistaken dispute?

For each persona, the first reason given for its top match is disputed, exactly as a student would do it in the app. The persona then answers the follow-up questions honestly. Because these disputes are deliberately mistaken (the persona really does have that trait, see the last row), a good system should both react to the objection and let honest follow-up answers correct it.

| Measure | Value |
|---|---|
| Personas contested | 30 |
| Top match changed after the contest | 100% (30/30) |
| Top-3 set changed after the contest | 90% (27/30) |
| Average drop in confidence of the disputed attribute | 0.72 |
| Average drop in the match's confidence | 0.17 |
| Follow-up questions asked (mean) | 2.8 |
| Original top match back on top after the follow-ups | 0% (0/30) |
| ...of those where the contest had changed the top match | 0% (0/30) |
| Original top match still in the top 3 after the follow-ups | 20% (6/30) |
| Disputed attribute level: before, after contest, after follow-ups | 0.76, 0.50, 0.50 |
| Disputed attribute confidence after follow-ups | 0.00 |
| Average true lean of the disputed attribute | 0.53 |

- **Changed after the contest**: the dispute alone, before any follow-up answers.
- **Drop in confidence**: confidence before minus after, on the 0 to 1 scale. Evidence is never deleted, so a dispute makes the belief contradictory and less certain rather than flipping it.
- **Back on top**: the top match after the follow-up answers is the original one.
- Why honest follow-ups don't restore it: a dispute adds counter-evidence as strong as the evidence it disputes, so support and contradiction end up about equal. Confidence is multiplied by (1 - conflict), where conflict = 2 x min(support, contradiction), capped at 1. Once contradiction is 0.5 or more, conflict stays at 1 however much new support arrives, so the attribute stays at a neutral 0.5 with zero confidence.
